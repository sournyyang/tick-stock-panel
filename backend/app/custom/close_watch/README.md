# 当天尾盘信号监控

L2扩展：复用路由注册/lifespan、ScreenerService、StrategyDataContext、
StrategyEngine.prepare_realtime_matrix、MatrixStrategyPipeline、alert_store和站内SSE。
不接模拟账户，不登记实际持仓，不创建委托，不模拟资金、股数或成交。
前端插入既有扩展监控页，核心回测、策略公式和行情采集保持不变。

## 信号流程

- 默认北京时间14:50开始，当天立即发买入候选和卖出预警，不等第二天。
  15:00后等待行情服务收盘定版，再分别给确认或未获确认记录。
  尾盘预警会变化；当前历史回测按次日开盘成交，不能把其收益套用于尾盘当天成交。
- 自动观察本策略收盘确认买点之后的卖点，不声称用户已经买入。
  首次启用依据可用历史的原生买卖信号补入尚未结束的观察，不补发历史通知。
  预警买点不提前假定成交，收盘取消的预警不会成为正式观察。
- 新买点不重置已有观察的原信号日和防守线。原信号日读取矩阵
  entry_close_floor；前复权价格同口径比较，原价展示用当日raw_close/close换算。
  原买点历史不可用时明确显示待核对，不猜防守线。
- 只对活动买点观察判断卖点，不能把全市场所有MA3下方股票当卖出通知。
  卖点为原策略退出条件、原买点防守线或有限观察期限。
  当前两仓60%策略为买点后第8个市场交易日尾盘到期观察，对应原回测
  信号次日开盘入场、第8持有日开盘退出的前一尾盘。这里没有实际持仓年龄。
- 当天新确认买点不同时当作已买已卖的往返交易。已有观察的卖点优先于
  同标的新买点；卖点收盘确认后结束本次信号观察，不表示已实际卖出。
  预警卖点若收盘恢复，保留原观察并发未获确认记录。
- 观察也可能来自回测中因满仓或无法成交而跳过的买点；模块不推断真实仓位、
  现金、可卖股数或是否成交。实际交易及两仓60%资金控制由用户自行执行。
- 支持股票日线矩阵、策略自身日选1只、原回测买卖次日开盘口径。
  额外overlay或其他保护性风控暂明确拒绝，避免静默遗漏。绑定校验代码、META
  和已保存调参指纹，变化时停止评估；重新保存绑定会重新建立观察。

## 数据和时效

只使用当日全市场实时快照，日期必须一致并含quote_ts原始毫秒时间戳。
预警要求行情整体及对应标的更新时间不超过180秒；收盘沿用行情服务的定版边界
（逐标的quote_ts至少14:59:55，5秒容差），final_sync_done且无失败状态才确认。
旧日、空、缺时间戳、暂停或陈旧数据均不伪装为无信号。最高候选陈旧时不从低排名补位。
周末不评估；工作日休市由当日行情及真实时间戳守卫，不能拿上个交易日数据重放。

一个daemon每15秒检查，只有启用且在尾盘/收盘窗口才计算。当天收盘完整确认后停止重复计算，保留该次确认结果；行情缺失时继续重试。初次装配历史，后续
只更新共享实时矩阵最新行；历史修复世代变化时重建。重计算不持状态锁，并发
配置修改通过generation优先于旧计算。SQLite排他租约避免多进程重复发信号。

## 记录和接口

数据仅在data/user_data/extensions/close_watch/：版本1状态JSON与runner租约。
JSON原子写，损坏或未知版本拒绝覆盖。保存观察、最近200条记录、按日/阶段的
去重ID和持久化outbox。先保存outbox再追加现有告警；检查点之间崩溃时按告警ID
恢复去重。预警、收盘确认分别去重，一只观察的多个卖出原因合并为一条。

API：GET /api/custom/close-watch/state、PUT /api/custom/close-watch/config、
PUT /api/custom/close-watch/dingtalk（严格布尔enabled）、POST /api/custom/close-watch/dingtalk/test。
没有账户、持仓登记或交易端点；HTTP不触发全市场同步扫描。前端查询键与请求
集中在closeWatchClient.ts，每15秒刷新。状态含来源日期和最近检查时间。

信号复用alert_store及QuoteService.push_alerts，进入监控中心和站内提醒；
钉钉开关独立，默认关闭，复用全局保存的机器人及加签配置，不在本模块保存凭据。
只排队启用之后的新预警、收盘确认及未获确认事件，不补发历史信号。
独立发送线程每秒取一条持久化队列，HTTP单次尝试，不阻塞行情/矩阵计算。
预警超过120秒或已收盘、确认超过600秒、跨日、暂停监控或更换绑定均不发送。
发送前落盘sending；重启遇到sending标记结果未知，不自动重发，避免网络歧义重复。
失败保留可见状态，不自动重试。钉钉返回成功仅表示机器人已接收，不表示用户已阅读。
连接测试明确标注非买卖信号，每分钟最多一次。收盘消息明确标注当日已无法执行。
数据dingtalk.json保存开关、队列和最近200条终态；ID独立持久化，同日重启去重。
已有普通监控规则及其全天时段/推送渠道独立保留，
模块不会改写它们；只想要尾盘提醒时可自行暂停同策略的普通规则。

模块不保证行情离线期间的即时预警，也不保证成交。移除扩展不删除历史记录，
更不改变真实账户。升级时需复核实时矩阵、数据世代、告警与扩展生命周期契约。
