# 钉钉群机器人通知

设置 → 实时监控 → 推送通知 → 钉钉，可配置群自定义机器人的 Webhook 和可选加签密钥。

## 接入

1. 在目标钉钉群添加自定义机器人，建议选择「加签」安全设置。
2. 复制原始 Webhook：`https://oapi.dingtalk.com/robot/send?access_token=...`。
3. 在钉钉配置行展开表单，填写 Webhook；若启用了加签，同时填写 `SEC...` 密钥。不要手动追加 `timestamp` / `sign`，适配器会为每次请求计算。
4. 保存后点「发送测试消息」，并在群内确认收到消息。接口成功仅表示钉钉返回 `errcode=0`。
5. 勾选钉钉可将其设为**新建监控规则的默认渠道**；已有规则需在规则编辑页勾选钉钉。个股价格预警也支持选择钉钉。
6. 在每日复盘页独立勾选钉钉，并保留原有手动/自动推送方式；配置机器人本身不会开启复盘自动外发。

加签密钥保存到现有 `secrets.json`（权限 0600）。展开配置表单后，Webhook 地址和已保存的加签密钥均以明文显示。删除密钥内容后保存或点击「清除加签密钥」会删除密钥；「清空配置」会同时清除地址和密钥。只修改地址时保留原密钥。

密钥通过专用配置读取接口返回（`Cache-Control: no-store`），只进入该表单的内存查询，不进入全局偏好和浏览器持久化查询缓存。读取失败时禁止保存，避免误覆盖已有配置。

## 失败与消息长度

- 告警使用文本，复盘使用 Markdown。正文超过 18,000 个 UTF-8 字节时保守截断，附带应用内查看提示，不会拆成多条刷群。
- 只有 HTTP 200 且整数 `errcode=0` 才判成功。签名、关键词、IP 安全设置或限流造成的业务拒绝不自动重试；网络异常和 HTTP 5xx 最多尝试 3 次。
- 设置页测试只尝试一次，使用已保存配置。失败时页面区分连接超时、签名不匹配、时间戳、关键词和 IP 白名单等原因；后端日志只记录脱敏原因、业务错误码或异常类型，不记录 Webhook、密钥、签名和响应原文。
- 若使用关键词安全设置，所有消息都必须满足群机器人配置的关键词；不同告警标题和复盘标题可能不同，建议使用加签。IP 白名单需要允许实际发送服务的出口 IP。
- 监控沿用现有后台投递线程池、规则冷却和站内告警流程；钉钉失败不阻断站内通知。复盘沿用现有归档和推送门控。

官方协议：[自定义机器人接入](https://open.dingtalk.com/document/robots/custom-robot-access)、[安全设置](https://open.dingtalk.com/document/robots/customize-robot-security-settings)。

## 二开边界

本实现是 **L3 源码适配模块**，不是可安装的 `plugin.yaml` 通知插件。当前 `plugin.yaml` 用于数据源，后端扩展注册只有通知文案格式化，没有投递通道注册接口，设置页也没有通知通道插槽。

钉钉协议独立放在 `backend/app/services/dingtalk_adapter.py`，配置 UI 独立放在 `frontend/src/pages/settings/DingtalkWebhookChannel.tsx`，其余核心改动仅接线。升级时重点核对偏好和 secrets getter、settings API、监控渠道白名单与线程池投递、复盘投递，以及前端 API 类型和渠道选择入口。开发基线为 `f249f863e48ec2219b008cdf022e7ceca99bbae6`，工作区已有未提交二开修改。

新增偏好字段缺省为空，未配置或未选择钉钉时不会投递；旧版 `webhook_enabled` 的迁移仍只选择飞书和企业微信。复用偏好/secrets 的文件缓存和前端 preferences 查询失效，不改变行情、策略或金融数据。
